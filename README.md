# 生活手账· Life Book

一个自己用的个人生活记录应用：**零构建的 H5 前端 + 轻量 Android 壳**。
深色主题、前端零第三方依赖、无打包步骤。

在线体验：<https://life-book-18142.app.workbuddy.host/> （邮箱注册登录）

## 它能做什么

底部六个标签：

| 标签 | 内容 |
|---|---|
| 今日 | 当日概览 + 记录星环 + 心情 / 喝水打卡 + 快速记录 |
| 记账 | 支出收入记录、分类统计、月度图表 |
| 日记 | 正文写作、全文搜索、按心情筛选 |
| 生活 | 随手记 + 自定义标签（可增删、可隐藏、可筛选） |
| 运动 | 步数、距离与消耗估算、运动记录 |
| 健康 | 体重等个人健康记录 |

**记录星环**（今日页）：一周七天的环形进度，点亮= 当天有记录，断签就是灰的缺口。
直接读真实数据，不是贴图。

**心情**：13 个**手绘 SVG 圆脸**，按情绪极性分四色（黄=积极 / 绿=中性 / 蓝=消极 / 粉=不满）。
不用 emoji —— emoji 由系统字体渲染，安卓和iOS 长相完全不同，也给不了颜色分组。
「本月心情」月历能看这个月哪天记了，任意一天可补记或改掉。

**喝水**：环形进度 + 快捷水量（200 / 500 / 自定义）+ 撤销。**每日目标可改**（500~5000ml）。

**背景**：粒子星点4 档强度 + 4 张自定义底图（可模糊、可调位置）+ 粒子颜色
可跟随主题或时间（深夜偏冷偏暗，白天偏暖偏亮），两个开关相互独立。

**周报**（在「我的」页顶部进入）：按周汇总记账 / 运动 / 日记 / 生活，
可前后翻最近 13 周，实时计算、不落库。

**月报**（「我的」页 → 每月回顾）：同一个自然月口径的总量与结构 ——
本月支出收入、环比上月、支出分类 Top 5、日记摘要、运动量、健康、步数达标线，
可往回翻最近 12 个月。刻意与周报错开：周报看「周内节奏」，月报看「一个月的样子」。

## 几个刻意为之的细节

- 图表全部**手写内联 SVG**，不引任何图表库（挂 CDN 图表库不可靠）
- 心情的 13 张脸是**参数化生成**的（眼睛 / 嘴巴 / 眉毛 / 装饰各是一个函数），
  不是13 张独立图片 —— 改脸型只改一处，风格天然统一
- 中文输入法友好：搜索框打字不会因为重绘被打断
  （能粘贴却打不出字，就是 DOM 被重绘把 composition 打断了）
- **切页秒开**：页面数据带指纹缓存，切回上一个标签时先用旧数据渲染、后台静默刷新，
  指纹没变就不重画 —— 所以不会闪、也不会把滚动位置和输入框弄丢
- **Service Worker 缓存**：首屏之后 `app.js` / `app.css` 全部走浏览器本地缓存，
  实测二次打开传输量 **0 KB**（首屏 1104ms → 92ms）
- **断网有提示**：顶部一条状态条说明「显示的是上次的数据」，恢复联网后自动收起并刷新
- **加载失败可重试**：列表页失败时给一个「点此重试」按钮；已经有旧数据时只轻提示一句，
  不把整页替换成错误块
- 提示一律用应用内浮层，**不用 `alert()`**（安卓 WebView 里的 alert 又丑又会卡住界面）
- **周报里的日记摘要由模型读过原文再压成一句话**，不是把正文截断 ——
  按「日记 id + 正文指纹」缓存，改了正文自动失效；模型不可用 / 超时就在行上照实写
  「点开看原文」并给一个重试入口，**绝不退回截断、也不编内容**
- 步数按天去重入库、当天只增不减；距离 = 步数 × 步幅（默认 0.8 m），
  消耗 ≈ 步数 × 体重 × 0.00053（默认 60 kg），UI 明确标注「估算」
- 日期一律按本地时区处理（用 UTC 会让东八区凌晨的记录落到前一天）
- **云端写入后必须拿回带 `id` 的整行** —— 不然之后按 id 删改会打不中任何行，
  表现为「撤销后数字变了，刷新又回来」
- **安卓壳的入口地址每天换一次缓存键**（`?app=1&d=20261016`）：CDN 各边缘节点会把同一个
  固定 URL 的旧副本缓存很久、且不回源，写死的入口会让 App 一直停在旧版页面。
  每天换键后，当天首次打开必然回源拿最新，同一天内再打开仍走缓存
- **版本号只有一处**（`APP_VER`）：它同时决定「重新下载」的链接
  （`/download/life-book.apk?v=…`，换键才绕得开 CDN 里的旧包）和旧壳的升级提示

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 原生 JS + CSS | 无框架、无打包步骤，改完存盘刷新即可 |
| 后端 | WorkBuddy 云服务 | Postgres + 行级权限（RLS）+ 文件存储 + 邮箱认证 |
| 图表 | 手写内联 SVG | 挂 CDN 图表库不可靠 |
| 缓存 | Service Worker | 托管不给 Cache-Control，只能自己定策略 |
| Android | WebView 空壳 | 用 aapt2 / d8 / zipalign / apksigner 手动打包，不走 Gradle |

## 目录结构

```
.
├── index.html# 页面骨架，只 2.7 KB
├── app.35.js               # 主程序（约 253 KB）
├── app.35.css              # 样式（约 57 KB）
├── sw.js                   # Service Worker：app.* / sdk 走cache-first
├── sdk.index.global.js     # 云服务客户端 SDK（随页面分发）
├── download/               # 已签名的 Android 安装包
│   ├── life-book.apk       #   页面按钮用的固定名
│   └── life-book-1.6.apk   #   带版本号，换新文件名 = 换缓存键，一定下得到新版
└── android/                # Android 壳工程，见 android/README.md
```

### ⛔ 改代码必须同步改文件名版本号

`app.35.js` 里的 `32` 是**缓存键**，不是装饰。改了内容但URL 没变，
Service Worker 会把旧代码一直用着 —— 表现为「改了没生效」，且极难排查。

正确做法：改内容时 `app.35.js` → `app.35.js`，同步更新 `index.html` 里的
`src` / `href` 和 `sw.js` 里的 `VER` 与 `ASSETS`。

## 数据模型

9 张表，全部按 `owner_id` 做 RLS 隔离 —— 登录用户只能读写自己的行：

`expense` 收支 · `diary` 日记 · `life` 生活随手记 · `sport` 运动 · `health` 健康 ·
`steps` 步数 · `water` 饮水 · `mood` 心情 · `profile` 头像与偏好

其中 `water` 按每笔增量存一行（不做累加更新），`mood` 每天一行。

## 本地运行

前端没有构建步骤。但 `index.html` 只剩骨架，**直接双击打开会看不到界面** ——
浏览器的 `file://` 协议会拦掉外部 JS 引用（跨域限制）。需要起个静态服务：

```bash
python -m http.server8000
# 然后打开 http://127.0.0.1:8000/
```

连后端还需要在 `app.35.js` 里配置云服务的 `publishableKey`（见下）。

## 说明

- `app.35.js` 里含有云服务的 **publishable key**（`wbpk_…`）。它按设计就是给客户端用的
  公开标识，权限由服务端 RLS 兜底—— 拿到它也读不到别人的数据。仓库里的版本与线上一致。
- 壳工程**不含**签名证书（`*.jks` 已在 `.gitignore` 中），打包脚本从环境变量读 keystore 口令。
  首次运行会自动生成自签名证书，但**用它签出来的包无法覆盖安装线上版本**（签名不同）。
- 仓库里**没有**周报生成的 HTML —— 那些是导出用的静态文件，含完整个人记录，不进仓库。

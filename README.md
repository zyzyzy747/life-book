# 生活手账 · Life Book

一个自己用的个人生活记录应用：**零构建的 H5 前端 + 轻量 Android 壳**。
深色主题、前端零第三方依赖、无打包步骤。

在线使用：<https://life.zyzyzy747.ccwu.cc/>（自建后端，账号密码登录）

> **这个仓库放的是「构建产物」，不是源码。**
> 后端与构建脚本在私有仓库 `life-book-selfhost` 里。
> 这里的内容由 `node backend/tools/build-public.js` 生成后推上来，
> 手改这里的文件会在下次构建时被覆盖。

## 它能做什么

底部六个标签：

| 标签 | 内容 |
|---|---|
| 今日 | 当日概览 + 记录星环 + 快速记录 |
| 记账 | 支出收入记录、分类统计、月度图表 |
| 日记 | 正文写作、全文搜索、按心情筛选 |
| 生活 | 随手记 + 自定义标签（可增删、可隐藏、可筛选） |
| 运动 | 步数、距离与消耗估算、运动记录 |
| 健康 | 体重等个人健康记录 |

**记录星环**（今日页）：当月环形进度，点亮 = 当天有记录，断签就是灰的缺口。
直接读真实数据，不是贴图。

**背景**：粒子星点 4 档强度 + 4 张自定义底图（可模糊、可调位置）+ 粒子颜色
可跟随主题或时间（深夜偏冷偏暗，白天偏暖偏亮），两个开关相互独立。

**周报**（在「我的」页顶部进入）：按周汇总记账 / 运动 / 日记 / 生活，
可前后翻最近 13 周，实时计算、不落库。

**月报**（「我的」页 → 每月回顾）：同一个自然月口径的总量与结构 ——
本月支出收入、环比上月、支出分类 Top 5、日记摘要、运动量、健康、步数达标线，
可往回翻最近 12 个月。刻意与周报错开：周报看「周内节奏」，月报看「一个月的样子」。

**头像**：上传图片后压成 256×256 的 webp 存在自建后端，换设备登录也在；
不上传就用昵称首字。

## 几个刻意为之的细节

- 图表全部**手写内联 SVG**，不引任何图表库（挂 CDN 图表库不可靠）
- 中文输入法友好：搜索框打字不会因为重绘被打断
  （能粘贴却打不出字，就是 DOM 被重绘把 composition 打断了）
- **切页秒开**：页面数据带指纹缓存，切回上一个标签时先用旧数据渲染、后台静默刷新，
  指纹没变就不重画 —— 所以不会闪、也不会把滚动位置和输入框弄丢
- **Service Worker 缓存**：首屏之后 `app.js` / `app.css` 全部走浏览器本地缓存，
  实测二次打开传输量 **0 KB**
- **断网有提示**：顶部一条状态条说明「显示的是上次的数据」，恢复联网后自动收起并刷新
- **离线也能记**：断网时写入进 IndexedDB 队列，左下角显示「N 条待同步」，
  恢复后按顺序重放；每笔带 `client_op_id`，重复提交不会变成两条
- **加载失败可重试**：列表页失败时给一个「点此重试」按钮；已经有旧数据时只轻提示一句，
  不把整页替换成错误块
- 提示一律用应用内浮层，**不用 `alert()`**（安卓 WebView 里的 alert 又丑又会卡住界面）
- **周报里的日记摘要由模型读过原文再压成一句话**，不是把正文截断 ——
  按「日记 id + 正文指纹」缓存，改了正文自动失效；模型不可用 / 超时就在行上照实写
  「点开看原文」并给一个重试入口，**绝不退回截断、也不编内容**
- 步数按天去重入库、当天只增不减；距离 = 步数 × 步幅（默认 0.8 m），
  消耗 ≈ 步数 × 体重 × 0.00053（默认 60 kg），UI 明确标注「估算」
- 日期一律按本地时区处理（用 UTC 会让东八区凌晨的记录落到前一天）
- **主键是 UUIDv7**：离线写入时客户端自己生成，服务端原样保存，
  这样本地缓存、乐观护栏、重放队列用的是同一个 id，不会出现「本地一条、云端另一条」

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 原生 JS + CSS | 无框架、无打包步骤 |
| 后端 | **自建**：PostgreSQL 17 + PostgREST 16 + Node 网关 | 跑在自家电脑上，2 核 2 G 足够；经 Cloudflare Tunnel 对外 |
| 鉴权 | 自实现：scrypt + HS256 JWT | access 30 天、refresh 1 年；`/.cloud/*` 与 `/llm/*` 无 token 一律 401 |
| 数据隔离 | Postgres RLS | 40 条策略，按 `auth.uid()` 限定 `owner_id` |
| 模型 | DeepSeek（经网关反代） | API key 只在服务端，浏览器拿不到 |
| 图表 | 手写内联 SVG | 挂 CDN 图表库不可靠 |
| 缓存 | Service Worker | 自己定策略，API 响应绝不进缓存 |
| Android | WebView 空壳 | 用 aapt2 / d8 / zipalign / apksigner 手动打包，不走 Gradle |

### `sdk.index.global.js` 是什么

它**不是**原来的云服务 SDK，而是自建后端写的一个兼容层，
对外暴露同样的 `WorkBuddyCloud.createWorkBuddyCloud()` 接口：

| 模块 | 作用 |
|---|---|
| `database` | 把 `.from().select/insert/update/delete` 翻译成 PostgREST 请求 |
| `auth` | 登录、刷新、登出，对接自建鉴权 |
| `llm` | 周报日记摘要，走网关反代（流式） |
| `storage` | 头像上传与签名下载地址 |
| — | IndexedDB 离线队列：断网写入排队，联网后按序重放 |

所以 `app.js` 里那 82 处 `cloud.database.from(...)` 一行都不用改。

### ⛔ 版本号由构建生成，手工别碰

`index.html` 里的 `?v=1793205102778` 是**构建时间戳**，同时写进 `sw.js` 的
`VER` 与 `APP_VER`。改内容但 URL 不变，Service Worker 会一直用旧代码 ——
表现为「改了没生效」，且极难排查。

构建脚本每次都会换一批新 URL，所以正常流程下不需要你操心；
但**不要手动改这几个数字**。

## 数据模型

10 张表，全部按 `owner_id` 做 RLS 隔离 —— 登录用户只能读写自己的行：

`expense` 收支 · `diary` 日记 · `life` 生活随手记 · `sport` 运动 · `health` 健康 ·
`steps` 步数 · `water` 饮水 · `mood` 心情 · `checkin` 签到 · `profile` 资料

约定：

- 主键 `id` 是 **UUIDv7**，可客户端生成（时间有序，索引局部性好）
- 每张表有 `updated_at`（触发器维护）和多设备合并用的优先级
- 每张表有 `client_op_id uuid UNIQUE`，离线重放的幂等键
- `water` 按每笔增量存一行（不做累加更新），`mood` / `steps` 每天一行
- `profile` 里 `avatar` 存状态标记、`nick` 存昵称（两台设备共用）

## 本地运行

**不能直接双击 `index.html`**：`file://` 协议会拦掉外部 JS 引用。

```bash
python -m http.server 8000
# 打开 http://127.0.0.1:8000/
```

但只有前端的话，登录和所有数据都会失败 —— 需要先跑起自建后端
（PostgreSQL + PostgREST + 网关，见私有仓库 `life-book-selfhost`）。

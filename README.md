# 生活手账 · Life Book

一个自己用的个人生活记录应用：**单文件 H5 前端 + 轻量 Android 壳**。
深色主题、零构建、前端零第三方依赖。

在线体验：<https://life-book-18142.app.workbuddy.host/> （邮箱注册登录）

## 它能做什么

底部六个标签：

| 标签 | 内容 |
|---|---|
| 今日 | 当日概览 + 三项打卡（日记 / 运动 / 生活）+ 快速记录 |
| 记账 | 支出记录、分类统计、月度图表 |
| 日记 | 正文写作、全文搜索 |
| 生活 | 随手记 + 自定义标签（可增删、可隐藏、可筛选） |
| 运动 | 步数（当日英雄区 + 近 14 天柱图）、距离与消耗估算、运动记录 |
| 健康 | 个人健康记录 |

**周报**（在「我的」页顶部进入）：按周汇总记账 / 运动 / 日记 / 生活，
可前后翻最近 13 周，实时计算、不落库。

外加一套「签到养成」：进首页自动签到攒经验升级，宠物有 4 个形态 × 5 套皮肤。

## 几个刻意为之的细节

- 图表全部**手写内联 SVG**，不引任何图表库（单文件应用挂 CDN 图表库不可靠）
- 中文输入法友好：搜索框打字不会因为重绘被打断
  （能粘贴却打不出字，就是 DOM 被重绘把 composition 打断了）
- **切页秒开**：页面数据带指纹缓存，切回上一个标签时先用旧数据渲染、后台静默刷新，
  指纹没变就不重画 —— 所以不会闪、也不会把滚动位置和输入框弄丢
- **断网有提示**：顶部一条状态条说明「显示的是上次的数据」，恢复联网后自动收起并刷新
- **加载失败可重试**：列表页失败时给一个「点此重试」按钮；已经有旧数据时只轻提示一句，
  不把整页替换成错误块
- 提示一律用应用内浮层，**不用 `alert()`**（安卓 WebView 里的 alert 又丑又会卡住界面）
- **周报里的日记摘要由模型读过原文再压成一句话**，不是把正文截断 ——
  按「日记 id + 正文指纹」缓存，改了正文自动失效；模型不可用 / 超时就在行上照实写
  「点开看原文」并给一个重试入口，**绝不退回截断、也不编内容**
- 数据可导入导出：自家 JSON / 粘贴文本 / 第三方备份文件（直接选文件导入），按表去重
- 步数按天去重入库、当天只增不减；距离 = 步数 × 步幅（默认 0.8 m），
  消耗 ≈ 步数 × 体重 × 0.00053（默认 60 kg），UI 明确标注「估算」
- 日期一律按本地时区处理（用 UTC 会让东八区凌晨的记录落到前一天）
- **安卓壳的入口地址每天换一次缓存键**（`?app=1&d=20260928`）：CDN 各边缘节点会把同一个
  固定 URL 的旧副本缓存很久、且不回源，写死的入口会让 App 一直停在旧版页面。
  每天换键后，当天首次打开必然回源拿最新，同一天内再打开仍走缓存
- **版本号只有一处**（`index.html` 里的 `APP_VER`）：它同时决定「重新下载」的链接
  （`/download/life-book.apk?v=…`，换键才绕得开 CDN 里的旧包）和旧壳的升级提示

## 技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 前端 | 原生 JS + CSS | 单文件 `index.html`，约 235 KB，无框架、无打包步骤 |
| 后端 | WorkBuddy 云服务 | Postgres + 行级权限（RLS）+ 文件存储 + 邮箱认证 |
| 图表 | 手写内联 SVG | 单文件应用挂 CDN 图表库不可靠 |
| Android | WebView 空壳 | 用 aapt2 / d8 / zipalign / apksigner 手动打包，不走 Gradle |

## 目录结构

```
.
├── index.html              # 整个 H5 应用（单文件）
├── sdk.index.global.js     # 云服务客户端 SDK（随页面分发）
├── pet/                    # 宠物立绘 webp：5 套皮肤 × 4 个形态
├── download/               # 已签名的 Android 安装包
│   ├── life-book.apk        #   页面按钮用的固定名
│   └── life-book-1.5.apk    #   带版本号，换新文件名 = 换缓存键，一定下得到新版
└── android/                # Android 壳工程，见 android/README.md
```

## 数据模型

9 张表，全部按 `owner_id` 做 RLS 隔离 —— 登录用户只能读写自己的行：

`expense` 支出 · `diary` 日记 · `life` 生活随手记 · `sport` 运动 · `health` 健康 ·
`steps` 步数 · `checkin` 签到 · `pet` 养成状态 · `profile` 头像与偏好

前端没有构建步骤，直接开 `index.html` 就能看到界面。要连后端需要在 `index.html` 里配置
云服务的 `publishableKey`（见下）。

## 说明

- `index.html` 里含有云服务的 **publishable key**（`wbpk_…`）。它按设计就是给客户端用的
  公开标识，权限由服务端 RLS 兜底 —— 拿到它也读不到别人的数据。仓库里的版本与线上一致。
- 壳工程**不含**签名证书（`*.jks` 已在 `.gitignore` 中），打包脚本从环境变量读 keystore 口令。
  首次运行会自动生成自签名证书，但**用它签出来的包无法覆盖安装线上版本**（签名不同）。
- 仓库里**没有**周报生成的 HTML —— 那些是导出用的静态文件，含完整个人记录，不进仓库。
